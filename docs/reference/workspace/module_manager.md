# Module Management

The `ModuleManager` class in BenchPRO is responsible for creating and managing [Lmod](https://lmod.readthedocs.io/en/latest/) environment module files for applications. These module files allow users to easily load applications and their dependencies into their environment.

## Overview

Environment modules provide a way to dynamically modify a user's environment variables such as `PATH`, `LD_LIBRARY_PATH`, and others. BenchPRO creates module files for applications, which contain information about:

- The application itself (name, version, description)
- Required dependencies
- Environment variables
- Binary paths

## Module File Creation Process

The module file creation process in BenchPRO follows these steps:

1. **Configuration Extraction**: The `Application` task extracts information from the configuration, including:
   - Application name and version
   - Module dependencies
   - Module paths
   - Workspace directory

2. **Module File Path Resolution**: The system determines the path where the module file will be created using the pattern:
   ```
   [workspace_dir]/modulefiles/[app_name]/[app_version].lua
   ```

3. **Template Rendering**: A Jinja2 template is used to generate the Lua module file with the following sections:
   - Module metadata (name, version, creation date)
   - Description
   - Module path configuration
   - Dependencies
   - Path configurations
   - Environment variables

4. **File Writing**: The rendered template is written to the module file path.

5. **Verification**: The created module file is verified to ensure it contains all required elements.

## Module File Structure

A typical module file generated by BenchPRO has the following structure:

```lua
-- [app_name] [app_version] module file created by BenchPro
-- Created on [date]

local name = "[app_name]"
local version = "[app_version]"

-- Description
whatis("Name: [app_name]")
whatis("Version: [app_version]")
whatis("Description: Application built by BenchPro")

-- Load dependencies
prepend_path("MODULEPATH", "[module_path_1]")
prepend_path("MODULEPATH", "[module_path_2]")
depends_on("[dependency_1]/[version]")
depends_on("[dependency_2]/[version]")

-- Add application binary directory to PATH
prepend_path("PATH", "[workspace_dir]")

-- Set environment variables
setenv("BP_[APP_NAME]_DIR", "[workspace_dir]")
```

## Module Dependencies

BenchPRO handles two types of module dependencies:

1. **Module Paths**: Directories where dependency modules can be found, specified in the application YAML configuration under `environment.module_paths`. These are added to the module file as `prepend_path("MODULEPATH", "[path]")` commands.

2. **Module Dependencies**: Actual modules that the application depends on, specified in the application YAML configuration under `environment.modules`. These are added to the module file as `depends_on("[module]/[version]")` commands.

### Example Configuration

```yaml
environment:
  module_paths:
    - "/path/to/modulefiles"
  modules:
    - name: "intel"
      version: "24.0"
    - name: "impi"
      version: "21.11"
```

## Integration with Application Tasks

Module file creation is integrated with the application build process:

1. The `Application.run()` method builds the application using the parent `Task.run()` method.
2. After a successful build, `Application.run()` calls `ModuleManager.create_module_file()` to create the module file.
3. The module file path is included in the application metadata stored in the application registry.

## API Reference

### ModuleManager Class

The main class responsible for module file creation and management.

#### Methods

- **create_module_file(app_name, app_version, workspace_dir, dependencies, binary_path, module_paths)**:  
  Creates a module file for an application with the given parameters.

- **extract_dependencies_from_config(config)**:  
  Extracts module dependencies from a configuration dictionary.

- **extract_module_paths_from_config(config)**:  
  Extracts module paths from a configuration dictionary.

- **get_module_file_path(app_name, app_version, workspace_dir)**:  
  Gets the path to a module file.

- **verify_module_file(module_file_path)**:  
  Verifies that a module file exists and is properly formatted.

- **validate_modules(modules, module_paths)**:  
  Validates that specified modules exist and can be loaded.

## Best Practices

When working with BenchPRO's module system:

1. **Always specify complete module information**:  
   Include both name and version for dependencies to ensure proper resolution.

2. **Use absolute paths for module paths**:  
   Module paths should be absolute to ensure they can be found regardless of where the module is loaded.

3. **Validate modules before building**:  
   Use the validation functionality to ensure all required modules exist before attempting to build an application.

4. **Include module_paths in your configuration**:  
   If your application requires modules not in the standard module path, include the appropriate module_paths in your configuration.

## Troubleshooting

Common issues with module file creation:

- **Missing dependencies**: Ensure all dependencies specified in the configuration exist.
- **Permission issues**: Verify you have write permissions to the workspace directory.
- **Invalid module paths**: Check that all module paths specified are valid and accessible.
- **Module file validation failures**: Review the module file to ensure it contains the required elements (prepend_path, whatis, setenv).
